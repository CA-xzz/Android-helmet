# 测试计划

## 原则

自动测试证明软件行为，模拟器用于提前验证流程。最终需求必须使用真实开发板、外部模块和后台环境取得证据。

## 自动测试

```sh
./tools/test-android.sh
./tools/test-backend.sh
python3 tools/validate-requirements-traceability.py
```

Android 测试覆盖协议、Room 迁移、定位、围栏、媒体、通话、广播、HTTP 设备命令自动轮询、安全检测、原始样本到告警和 SET_OUTPUT 的运行路径、离线恢复和硬件服务。后台测试覆盖身份隔离、轨迹、媒体、通话、广播、语音、告警、审计、数据库、对象存储和 MQTT。

状态心跳板测必须由前台服务触发启动状态、服务器校时重发和周期心跳，不得在等待循环中直接调用 DeviceStatusWorker。

安全告警自动上传板测必须通过前台服务输入触发样本和告警，由服务自动调度 SafetyAlertWorker。测试不得直接写入告警、调用 Worker 或调用告警上传接口。

告警处置板测必须使用设备端自动上传的告警，验证提醒字段、只读角色拒绝、确认、处理中、关闭、操作者历史和后台重启持久化。模拟告警只能验证软件链路，不能替代真实现场验收。

离线恢复板测必须先使用远端地址调度轨迹、媒体和告警 WorkManager 任务，确认无默认网络时任务保持等待；终止进程后切换到 ADB 回环地址，只调用正式调度入口，验证旧路由任务取消、新路由任务自动上传和重复执行幂等。恢复阶段不得直接执行 Worker。

大队列板测必须写入超过单次 Worker 上限的轨迹、媒体、告警和通信记录，只调用一次正式调度入口，并确认 WorkManager 追加后续任务直至队列清空。测试期间不得通过新增事件或网络切换再次触发调度。

通信恢复板测必须先持久化待发送通话、已应用但未确认的命令及未发送的广播最终回执，使用远端地址保持 WorkManager 任务等待，再强制终止测试进程。恢复阶段只调用正式调度入口，验证通话、命令确认和从 RECEIVED 开始的广播回执序列均送达，且传输错误不会覆盖原始播放错误。

应用启动恢复板测必须在服务停止且 WorkManager 任务已取消时写入 attemptCount 为 0 的轨迹、媒体、告警和通信记录，并为多分片媒体预置首个服务端分片，再强制停止主应用。恢复阶段只允许通过应用初始化启动 HelmetService，不得由测试调用 Worker 或其 enqueue 方法；四类记录必须自动送达并可从后台查询，媒体必须从服务端 nextOffset 续传且不得重复首片。

本地事件日志只用于诊断和审计。轨迹、媒体、告警、状态和通信分别使用专用持久化记录及上传任务，不把本地事件日志计为待上传队列。

## 开发板基础

使用 ADB 序列号 `2c001031774186e21d3`：

1. 构建并安装 APK。
2. 启动前台服务。
3. 验证开机恢复、进程终止恢复和日志。
4. 验证 Room 数据在重启后保留。
5. 验证 UART 打开关闭、非法路径拒绝和模块断开恢复。
6. 记录 APK 摘要、系统版本、测试命令和结果。

## 5.1 定位

- 普通定位：在已知点和移动路线采集真实 GNSS/基站融合数据，统计水平误差，目标 0 至 5 米。
- RTK：在已知基准点使用固定解，记录接收机、天线、差分服务、HDOP、卫星数和误差，目标不大于 0.5 米。
- 轨迹：验证时间和顺序、断网缓存、重启恢复和补传。
- 围栏：真实跨越边界，验证本地报警、后台标记和处置。
- 围栏软件回归：从外部用户态 UART 输入合成 HSL RTK_NMEA，核对生产定位服务自动生成退出和返回事件、Room 交付状态及后台事件顺序。测试不得直接写入告警、调用 Worker 或调用上传接口；该回归不替代真实 GNSS 和人员越界。
- 管理端：同时显示人员、位置、轨迹、视频、电量和电压；验证页面可见时自动刷新、后台页面暂停请求、返回页面立即恢复、新告警和呼叫提示及角色隔离。

## 5.2 媒体

- 真实按键触发拍照、开始录像和停止录像。
- 验证 1080P 分辨率、帧率、连续时长、温升和文件可播放性。
- 配置人员编号后核对状态心跳和真实媒体使用同一编号，并核对时间、位置、设备、告警事件、大小和 SHA-256。
- 在线自动上传；断网、重启后恢复分片上传；重复提交不产生重复归档。

## 5.3 通信

- 物理键发起语音和视频呼叫。
- 后台接听、拒绝、挂断，设备播放对应提示。
- 管理端接听后不发送手工服务指令，确认设备通过持久呼叫状态自动创建 Offer；浏览器提交 Answer 和 ICE 后确认设备应用 Answer；挂断后确认设备关闭会话并恢复空闲状态。每页信令读取上限为 100。
- 在呼叫已持久化为 `CONNECTED` 时终止并只重启前台服务，确认设备创建新 Offer；后台概览返回其精确序号，管理端只选择该 Offer，设备不应用重启前的旧 Answer。随后从管理端挂断并核对 Room 终态和 WebRTC 关闭事件。
- 验证真实麦克风、扬声器、摄像头和 STUN/TURN。分别在无网络、计费、漫游、下行低于 1000 Kbps、上行低于 500 Kbps 场景确认初始快照、通话建立前策略保留、通话中降级、网络恢复和媒体重连。
- 发送文字广播，核对送达、播放和失败回执。
- 未配置 MQTT 时，在前台服务运行期间发送后台命令，确认设备无需手动同步即可获取命令并返回确认。
- 保留旧版 WorkManager 数据并覆盖安装，验证当前传输任务不会被遗留网络约束任务阻止。
- 上传并播放真实语音消息，验证角色和组织隔离。
- 使用专用 LoRa 语音硬件测试距离、穿透、单向时延、丢包和可懂度。

## 5.4 安全动作

- 使用标注动作集测试碰撞、跌落和晃动，计算识别率、误报率和漏报率。
- 验证报警自动关联真实位置和现场媒体。
- 先上传告警、后归档同一设备和事件的照片或视频，验证告警详情动态补出媒体 ID、原始告警重复提交仍幂等，并在管理端打开现场证据。
- 后台产生声音、画面和地图提醒。
- 验证确认、处理中、关闭及操作者审计。

## 5.5 近电

- 在受控安全条件下完成基线校准和各电压等级测试。
- 验证强度、累积值、等级和阈值。
- 验证语音、LED、振动本地报警。
- 断网时仍报警并缓存，恢复后自动上传。
- 软件回归使用生产前台服务输入模拟近电告警，核对 Room 与后台的样本引用、电场值、等级、位置质量、来源和交付状态；该回归不代替前四项真实硬件测试。

## 5.6 高度

- 确认基准、量程、精度和漂移。
- 移动过程中连续采样。
- 越过可配置阈值时验证语音、LED、振动和后台记录。
- 验证断网缓存和恢复补传。
- 软件回归使用生产前台服务输入模拟高度告警，核对 Room 与后台的高度、气压、等级、位置质量、交付状态和处置历史；该回归不代替前三项真实硬件测试。

## 证据

每次实机测试保存：

- 硬件型号、接线、配置和环境。
- 测试前准则和步骤。
- 原始日志、照片、视频、测量值或后台记录。
- APK 和代码提交摘要。
- 通过或失败结论及未解决问题。

证据存入 `docs/verification/`，并在 `docs/REQUIREMENTS_TRACEABILITY.md` 对应行引用。
