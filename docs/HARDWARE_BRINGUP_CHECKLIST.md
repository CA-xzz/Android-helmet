# H618 硬件 Bring-up 清单

本清单用于 `QUAD-CORE H618 p1` 的量产硬件接入。每次测试必须记录板号、BSP 版本、应用 APK SHA-256、外设型号、接线、供电条件、时间和操作者。

## 1. 开始前

- [ ] 使用 `adb devices -l` 确认唯一目标为 `2c001031774186e21d3`。
- [ ] 备份并记录主应用版本、配置、前台服务、进程、包路径和 APK 哈希。
- [ ] 采集设备树 alias、pinctrl、平台驱动绑定、`/dev`、I2C、ALSA、CameraService、SensorService、USB、存储、网络和输入设备基线。
- [ ] 确认测试不会卸载或清除 `com.example.helmet`，安装只使用 `adb -s 2c001031774186e21d3 install -r`。
- [ ] 确认不修改 `/data/myautorun.sh`、设备树、BSP、GPIO export、方向或值。
- [ ] 对照 `HARDWARE_PIN_MAPPING.md` 关闭所有冲突或未确认的控制项。

## 2. 原理图和物料确认门槛

- [ ] 解决 PI4 摄像头电源与 MMA8452 INT2 冲突。
- [ ] 确认 PG13 的 Linux GPIO 映射及其与现有 `gpio203` 的关系。
- [ ] 确认七根 LED/按键线的具体功能、输入输出方向、有效电平和默认状态。
- [ ] 确认 NAU88C2x 实际型号、I2C 地址、I2S 时钟、电源时序和 Android Audio HAL 接入方式。
- [ ] 确认 4G 模块型号，PG8/PG9 与 UART1 pinmux 的关系，PG10 的复位或关机语义。
- [ ] 确认 RTK 直连 UART4 或 HSL 转发拓扑及波特率。
- [ ] 确认每个电源域的最大电流、稳定时间、反灌风险和关断顺序。

任一项未确认时，相应资源保持未配置、冲突或等待外设，不进入物理控制测试。

## 3. 安全上电和关断

- [ ] 首次上电使用限流电源，记录 5 V 和 3.3 V 静态电流。
- [ ] 所有可控输出先保持原理图确认的非活动态；未知输出保持不操作。
- [ ] 只在测得电平和电源稳定时间后，将数值写入板型配置和 BSP 驱动。
- [ ] 上电顺序按硬件确认结果执行：公共电源稳定后，再启用单个外设电源，最后发送模块启动脉冲。
- [ ] 4G PWRKEY 仅在 PG9 脱离冲突并确认电气条件后执行 1 秒低脉冲；取消或异常时必须回到非活动态。
- [ ] 关断前停止拍摄、录音和通信，卸载或同步存储，再关闭单个外设，公共 3.3 V 最后关闭。
- [ ] 任一步失败时按已成功步骤的逆序回滚。不得用应用崩溃或进程退出代替安全关断。

当前代码没有连接未确认 GPIO，因此以上步骤在硬件确认和 BSP 驱动完成前只作为验收门槛。

## 4. 分模块检查

### Camera

- [ ] Camera2 枚举真实 UVC 摄像头，断开时状态回到等待外设。
- [ ] 验证短按拍照、长按 2 秒录像、1080p 录像、音频同步和文件完整性。
- [ ] 断电、热插拔、权限拒绝和采集失败不产生伪造媒体成功记录。

### Audio

- [ ] ALSA 和 AudioManager 枚举正确输入输出设备。
- [ ] 录音取得非零 PCM，回放无明显失真，再验证语音消息和 WebRTC。
- [ ] codec 缺失、权限拒绝、零 PCM 和路由切换均显示降级，不报告可用。

### 4G

- [ ] USB 或 UART 枚举与实际模块型号一致。
- [ ] Android 获得已验证的蜂窝网络后才显示运行。
- [ ] 验证弱网、掉线、重连和冷启动；不得通过复位循环掩盖驱动或 SIM 问题。

### MMA8452

- [ ] 硬件方案解决 PI5/PI6 与 UART2 冲突；量产 App 通过 HSL `SENSOR_SAMPLE` 接收 MMA8452 数据，不直接操作 I2C0。
- [ ] HSL HELLO 声明 `MMA8452_ACCELEROMETER`，心跳通过后再发送样本。
- [ ] 确认坐标方向、正负号、零偏和量程，使用静止六面法记录校准。
- [ ] 原始 SI 单位只在明确量程后转换为 milli-g；无数据、过期、饱和和总线故障可观测。

### RTK

- [ ] 默认 HSL 模式通过 `RTK_NMEA` 输入和 `RTK_CORRECTION` 输出。
- [ ] `/dev/ttyAS4` 直连时由硬件服务独占，不与 `/dev/ttyAS2` HSL 复用。
- [ ] 验证波特率、NMEA 校验、RTCM3 CRC、Fix 类型、差分龄期和断线恢复。
- [ ] 只有有效且新鲜的外部定位可显示运行；设备节点存在只表示已映射。

### SD1 和 SD2

- [ ] 插卡后由 StorageManager/vold 报告挂载，再执行容量、读写、同步和安全移除测试。
- [ ] 插入检测只用于诊断，不代替挂载、读写和数据完整性。
- [ ] 断电和热拔插后文件系统无新增错误。

### 按键和 LED

- [ ] HSL HELLO 声明按键、LED、振动和蜂鸣能力，缺少必需能力时 App 显示协议不兼容并阻止控制。
- [ ] 按键逐一确认功能，记录消抖时间、短按阈值、长按阈值和重复事件策略。
- [ ] 按下、松开、断线和服务重启后状态机不产生重复业务动作。
- [ ] LED 极性确认后验证优先级：活动报警、硬件故障、业务活动、网络离线、正常运行。
- [ ] LED 或按键缺失时显示未配置或等待外设，不以 InputManager 设备数量推断成功。

## 5. 软件回归

```sh
./tools/build-android.sh
./tools/test-android.sh
./tools/run-board-connected-software-tests.sh \
  --adb-serial 2c001031774186e21d3 \
  --hardware-device-path /dev/ttyAS2 \
  --hardware-baud-rate 115200
```

- [ ] `H618BoardProfile.validation.productionSafe` 为 true。
- [ ] H618 被动探针保持冲突项、未配置项和缺失外设的降级状态。
- [ ] `simulator_enabled=false`，生产串口为 `/dev/ttyAS2`、115200。
- [ ] 默认 RTK 模式为 `HSL`；选择 `DIRECT_UART4` 时只打开 `/dev/ttyAS4`，不影响 HSL 文件描述符。
- [ ] 模块契约主版本一致、次版本满足要求、必需能力齐全，HELLO 后心跳有效。
- [ ] 正常 `adb reboot` 后主应用版本保持，前台服务和独立硬件进程自动恢复。
- [ ] 重启后仍无测试包、临时后端、ADB reverse 和残留仪器化进程。

## 6. 验收判定

- [ ] 只有真实外设枚举、有效业务数据和端到端结果同时满足时标为通过。
- [ ] 软件闭环、PTY、模拟样本和设备节点存在只能证明软件路径，不作为外设通过。
- [ ] 未接外设记录为等待外设；驱动未接入记录为驱动缺失；冲突未解决记录为冲突。
- [ ] 截图、日志和测试结果不包含令牌、凭据或未脱敏业务数据。
- [ ] 所有临时测试包和端口映射已清理，主应用数据和现场配置保留。
