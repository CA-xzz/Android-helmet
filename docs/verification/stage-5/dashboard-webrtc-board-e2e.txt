## 修复和自动检查

管理端原先以 `limit=500` 读取呼叫信令，但后台接口上限为 100，因此实时视频入口会收到 HTTP 400。管理端现以 100 条分页读取。前台服务现观察 Room 中最新呼叫状态；设备命令写入 `ACCEPTED`、`CONNECTING` 或终态后，不依赖额外服务 Intent 即可启动或停止媒体会话并更新运行状态。

## 自动端到端步骤

1. H618 前台服务收到模拟 CALL 按键并创建 `REQUESTED`，呼叫自动上传到后台。
2. 本地同源管理端显示明显待接听卡片。操作员 `dispatcher-web` 点击接听。
3. 后台产生设备命令序号 4。H618 HTTP 轮询自动获取、应用并确认 `ACCEPTED`。
4. Room 状态观察器自动启动 `CallMediaCoordinator`。本次没有发送 `ACTION_CALL_STATE_UPDATED` 或其他手工唤醒指令。
5. H618 创建并上传 Offer，后台状态由 `ACCEPTED` 进入 `CONNECTING`，管理端自动出现“连接实时视频”。
6. 浏览器点击入口后读取 Offer，提交 Answer 和 ICE candidate。对话框显示“已应答，等待视频轨道”。
7. H618 轮询信令并记录 `WEBRTC_ANSWER_APPLIED`。
8. 操作员关闭对话框并点击挂断。后台产生设备命令序号 5，H618 自动应用并确认 `ENDED`，关闭 WebRTC 会话。最新设备状态为 `OFFLINE_READY`、`activeCallId=null`。

## 边界

- 呼叫由模拟按键产生，不是外置物理按键证据。
- H618 报告摄像头不可用，Offer 明确降级为 `videoEnabled=false`。
- `audioEnabled=true` 只表示 WebRTC 音频发送器配置完成，不证明麦克风采集、扬声器播放或声学质量。
- 浏览器收到 Answer 后保持等待视频轨道；ICE 停留在 `CHECKING`，没有形成媒体连接。
- 联调使用 ADB 反向端口、本地 HTTP 和测试 STUN 地址，没有验证公网 NAT、生产 TURN、TLS、RTP 媒体、真实弱网或双向音视频。
- 本记录证明管理端、后台、设备命令、持久呼叫状态和 WebRTC 信令的软件闭环，不作为第 5.3 条真实硬件最终验收。
