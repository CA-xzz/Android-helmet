目的

使用 H618 前台服务自动生成并上传的模拟跌倒告警，验证后台提醒字段、处置权限、确认、处理中、关闭、操作者历史和重启持久化。测试不直接写入样本或告警，不直接调用或入队 SafetyAlertWorker，也不直接向告警上传接口发送告警。

环境

- Android 的 Active default network 为 none，应用运行状态为 networkState=UNAVAILABLE。
- 隔离后台监听 http://127.0.0.1:18083，通过 adb reverse tcp:18083 tcp:18083 接入。
- 输入为 SimulatedInput.FALL，不是 IMU 实测数据。
- 本轮没有可信定位，location.fixType=NO_FIX。
- 后台使用开发单令牌模式和临时 SQLite 目录。处置完成后重启同一后台数据目录，再查询告警详情。

回归发现与修复

首次运行中，前台服务已保存模拟跌倒告警，但旧配置留下的 SafetyAlertWorker 待重试任务以 ExistingWorkPolicy.KEEP 阻止新的 loopback 任务，30 秒内没有执行上传。

SafetyAlertWorker 改为使用独立的 loopback 和 network 唯一任务名。路由变化或进程首次协调时取消旧任务名和另一条路由任务，保留同一路由上的 KEEP 语义。单元测试验证两条路由的任务名、互斥关系和 NetworkType。修复后的服务启动阶段先上传此前待处理告警，再自动上传本轮告警。
