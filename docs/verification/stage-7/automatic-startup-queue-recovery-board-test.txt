# H618 应用启动自动恢复持久队列

验证日期：2026-08-11（Asia/Shanghai）
开发板：QUAD-CORE H618 p1，Android 12/API 31
ADB 序列号：2c001031774186e21d3

## 验证方法

1. 安装 Debug APK 和 AndroidTest APK。
2. 启动使用 64 KiB 分片的隔离后台并建立 ADB reverse。
3. 第一阶段停止 HelmetService 并取消现有 WorkManager 任务，直接向 Room 写入一条待发送轨迹、一条 256 KiB 合成照片、一条合成近电告警和一条待发送通话。
4. 第一阶段直接向媒体会话写入照片的首个 64 KiB 分片，确认服务端 nextOffset 为 65536；四条本地记录的 attemptCount 仍为 0。
5. 保存回环后台配置，主机强制停止 com.example.helmet。
6. 第二阶段只通过 AndroidJUnitRunner 启动应用进程。HelmetApplication 自动启动 HelmetService，测试代码不调用 TrackUploadWorker、MediaUploadWorker、SafetyAlertWorker、CommunicationWorker 或其 enqueue 方法。
7. 等待 Room 中四条记录变为 DELIVERED，从后台逐条查询轨迹、媒体、告警和通话，并确认媒体完成事件只计入剩余 196608 字节。

测试轨迹坐标、照片字节和告警均为队列恢复夹具，不是 GNSS、摄像头或近电传感器证据。

## 结果

seed 阶段：

```text
Time: 1.613
OK (1 test)
```

主应用被强制停止后，recover 阶段由应用初始化自动启动前台服务：

```text
Time: 12.426
OK (1 test)
PASS: application startup recovered track, media, safety, and communication queues
media_preloaded_bytes=65536 media_resumed_bytes=196608 backend_media_chunks=4
backend_track_posts=1 backend_media_completes=1 backend_alert_posts=1 backend_call_posts=1
```

第二阶段断言进程 PID 与第一阶段不同。四类本地记录的 attemptCount 均由 0 增加，deliveryState 或 transferState 均变为 DELIVERED。媒体完成事件的 bytesUploaded 为 196608，隔离后台总计收到 4 个 64 KiB 分片，说明应用从服务端 nextOffset 继续上传，没有重复发送首个分片。隔离后台各收到一条对应资源写入。

## 结论与边界

H618 已证明主应用进程被终止后，应用初始化和前台服务启动会自动调度轨迹、媒体、告警和通信持久队列，不依赖测试显式调用 Worker；媒体上传能从后台保存的分片偏移继续。ADB 回环不替代真实 4G/5G 网络恢复、真实定位、真实摄像或真实传感器验收。
