# 管理端自动刷新回归

日期：2026-08-11
代码基线：83367bc 加本次管理端自动刷新改动
环境：Codex 内置浏览器、127.0.0.1:18091、本地 SQLite 和对象目录、开发单令牌身份

## 步骤

1. 启动隔离后台并打开 `/dashboard`。
2. 输入临时联调令牌和调度身份，手动执行首次连接。
3. 确认首次页面没有设备或告警，随后不再点击刷新。
4. 通过设备接口提交 `dashboard-device-1` 的真实来源状态，包含人员、位置、电池百分比和电压。
5. 通过告警接口提交同设备的 CRITICAL 跌倒告警。
6. 等待下一轮页面自动刷新，检查摘要、地图、设备卡片和告警卡片。
7. 核对后台请求日志中的刷新间隔和身份请求。

## 结果

- 首次成功连接后，页面约每 5 秒请求权限、告警、呼叫、广播、语音、媒体、设备汇总和地图配置。
- 状态和告警在 18:19:05 提交；18:19:10 自动轮询读取，未执行手动刷新。
- 页面显示 1 个待处理告警、1 个严重告警和 1 台设备。
- 地图显示设备和活动告警标记。
- 设备卡片显示 `person-dashboard`、31.23040/121.47370、68% 和 3.92 V。
- 告警卡片显示 FALL、CRITICAL、OPEN、地图定位、现场证据等待归档和更新处置入口。
- 开发单令牌身份首次连接执行兼容回退；身份模式确认后，后续自动刷新直接携带操作员身份，不再产生回退 403。
- 浏览器脚本语法检查通过，后端管理端资源测试覆盖自动刷新常量、调度函数和可见性监听器。

结论：管理端自动更新位置、状态和告警的软件路径通过。

## 边界

- 本测试使用本地后台和接口注入数据，不是开发板真实定位、电池或 IMU 证据。
- 浏览器控制环境中的新标签页没有使原页面进入隐藏状态，因此页面隐藏暂停请求只由代码路径和静态资源测试覆盖，仍需最终浏览器人工验收。
- 没有启用声音，未执行扬声器声学验证。
