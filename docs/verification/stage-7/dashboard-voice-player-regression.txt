阶段 7 管理端语音消息播放器回归
日期：2026-08-11

实现范围

1. Android MediaKind 新增 VOICE，并保存发送主体、发送角色、允许角色和可选呼叫 ID。
2. Room 从 v6 迁移至 v7。旧照片和视频记录保持不变，语音字段使用空默认值；新增持久化往返和 v6 到 v7 迁移测试。
3. MediaUploadWorker 复用既有断点上传、摘要校验、幂等完成和失败分类；VOICE 请求发送 durationMillis、senderId、senderRole、allowedRoles 和 callId，不发送图像尺寸、人员和位置字段。
4. 客户端在读取文件后验证语音 MIME、正时长、发送主体、发送角色、非空允许角色和可选呼叫 ID。无效元数据作为不可重试错误处理。
5. DISPATCHER、SUPERVISOR 和 ADMIN 具有 PLAY_VOICE_MESSAGES 能力；VIEWER 不请求受限列表。
6. 管理端播放器使用认证头读取 /v1/voice-messages/{messageId}/content，不把令牌写入 URL。页面要求 Content-Length，并核对实际长度、MIME、ETag 和 25 MiB 上限。
7. 关闭播放器或更换令牌会取消读取、停止音频、撤销 Blob URL，并清除旧组织语音列表。正文使用 Cache-Control: private, no-store。

证据边界

WAV 是 H618 测试包生成的 440 Hz 合成音，不是麦克风录音。后台使用本地 schema 2 身份夹具、SQLite、本地对象目录、HTTP 和 ADB reverse。浏览器控件进入播放状态不等于扬声器声学输出。结果证明 Android 语音媒体模型、Room、Worker、后台归档、授权浏览器解码播放、组织隔离和审计的软件闭环，不替代真实麦克风、扬声器声学测量、生产 PostgreSQL/S3/HTTPS、正式身份服务、生产网络、真实 WebRTC 通话或最终整机验收。
